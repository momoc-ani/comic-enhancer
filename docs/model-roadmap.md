# 模型路线与验收

## 首版模型组合

| 环节 | 首版选择 | 原因 |
| --- | --- | --- |
| 基础生成 | SD1.5 动漫 checkpoint | 8GB 到 12GB 显卡可运行，4090 可做秒级低步数推理 |
| 结构保持 | ControlNet Lineart SD1.5 | 直接利用漫画线稿，减少人物和构图漂移 |
| 画质增强 | Real-ESRGAN Anime 6B | 对动漫线条和低清页面成本较低 |
| 独立放大档 | Real-CUGAN SE 2x | 不经过上色模型，跨平台原生执行并固定无降噪 |

2026-08-14 对质量工作流做了三组 3 页冒烟 A/B。当前候选使用 20 步、CFG 6.8、denoise 0.70 和 Lineart ControlNet strength 1.02；远端完整 API 热推理 3/3 成功，P50 5.416 秒、P95 5.549 秒，墨线、中文和白底结构保留正常，有效色相中位数为 5，最差页主导色占比为 51.95%。但最终饱和色覆盖中位数只有 3.06%，人工检查仍以灰白和浅色点缀为主，不能判定当前 SD1.5 全页方案达到目标画质。本轮只作为保守增量改进，最终结论仍需新的模型路线和至少 100 页授权集。

## 后续候选基准

使用至少 100 页、经过授权的测试集比较：

当前已增加 `scripts/benchmark_api.py` 和 `benchmarks/` 清单格式，可记录完整 API 的实际模型档位、角色参考生效情况、耗时、尺寸、明度与深色墨线保留。现有 3 页仅作为本地非商用冒烟集；详细准入门禁见 `benchmarks/README.md`。

- DDColor-Tiny：ONNX 速度基线，不作为漫画最佳效果的默认结论。
- manga-colorization-v2：漫画专项研究基线，发布前必须重新核对代码和权重许可证。
- SD1.5 Anime + Lineart ControlNet + IP-Adapter：8GB 主力候选。
- Cobra 多参考上色：第一候选，代码和权重均为 Apache-2.0；分别测试 2、4、8、12 张参考图，并记录 PixArt/T5 常驻显存、首轮加载时间与热推理耗时。
- FLUX.2 Klein 4B FP8：第二候选，Apache-2.0 蒸馏 4 步路线；使用同一批漫画页和角色参考图对比人物颜色一致性、文字/墨线保持、颜色丰富度、耗时和显存。只有同集实测优于 Cobra 时才切换默认高质量候选。
- Real-ESRGAN Anime 6B：测试 1x 修复、2x 输出和文字线条清晰度。
- Real-CUGAN SE：独立放大档固定测试 2x、无降噪输出，记录文字、气泡、网点、细线、耗时、Vulkan 设备和连续页面稳定性；Windows、Linux 和 macOS 平台结果必须分别记录。

2026-08-16 的 Anima Base 与 Anima-2.9B 本地冒烟结果不满足“只上色、不重绘”门禁：Base 明显重绘人物、场景和文字，2.9B 约 15.5 秒且基本灰度并改写文字；参数扫描也未找到颜色覆盖与线稿/文字保持的可用窗口。因此两条实验实现已从项目中移除，不进入默认或实验路由。

2026-08-17 增加两个默认关闭的 FLUX.2 验收档位：`flux2_9b_lora` 固定 9B FP8 + Qwen3 8B FP8 mixed + 一致性 LoRA 0.6 + 四步空 latent，作为当前画质对照；`flux2_4b_source` 固定 4B FP8 + 一致性 LoRA 0.35 + 四步 source latent + CFG 1.3 + denoise 0.65，作为快速结构稳定对照。两档均使用最多三张角色参考图、ComfyUI 原图尺寸直出和 Real-CUGAN 2x，不依赖逐页 VLM 分析。ControlNet 仅作为后续结构约束实验，完成独立 A/B 前不合入这两个基线参数。

同日追加 `flux2_4b_color` 色彩增强验收档：保持 4B source latent 链路和速度参数不变，仅将一致性 LoRA 从 0.35 调整为 0.25。既有四页扫描的平均饱和色覆盖为 36.34%，高于结构稳定档的 32.96%，暗线保留约 95.28%、白区保留约 85.26%。该档与 `flux2_4b_source` 并存，扩大授权集验证前不替换默认画质路线。

同日完成 FLUX.2 Klein ControlNet 兼容性调研。远端已挂载的 FLUX.1 Union Pro 2.0 和 Canny v3 在 4B Klein 采样时触发张量维度错误，不能跨架构复用；公开模型仓库未找到 FLUX.2 Klein 4B 专用 ControlNet。FLUX.2-dev Union 是不同架构且权重约 8.23GB，并受 FLUX dev 非商用许可证限制；Klein 专用 RefControl Lineart/Canny LoRA 目前仅面向 9B。因此不增加必然失败的 4B ControlNet 挡位，等待架构和许可证均明确兼容的权重后再做独立 A/B。

同日增加默认关闭的 `flux2_9b_fast` 独立实验档。它复用 9B FP8、Qwen3 8B FP8 mixed、一致性 LoRA 0.6、四步空 latent 和三张角色参考图，只将 ComfyUI `UNETLoader.weight_dtype` 从 `default` 切换为 `fp8_e4m3fn_fast`。四张不同漫画页的 ComfyUI 内部热执行均值由 6.856 秒降至 5.185 秒，约快 24.4%；饱和色覆盖均值由 31.28% 变为 30.93%，逐页平均绝对像素差为 1.85 到 2.73/255。第四页暗线保留下降约 3.07 个百分点，所以该档只作为速度候选并与 9B 画质基线并存。

同日追加默认关闭的 `flux2_9b_fast_lowres` 低分辨率快速实验档。它完整复用 `flux2_9b_fast` 的模型、LoRA、提示词、三张参考图、四步采样和 Real-CUGAN 二阶段，只将漫画页推理尺寸从 `0.85MP` 降为 `0.70MP`。四页 A/B 的 ComfyUI 内部热执行均值从 5.217 秒降至 4.780 秒，仅快 8.4%；平均饱和色覆盖从 30.93% 提高到 40.36%，但平均暗线保留从 95.88% 降至 90.83%，第四页降至 74.35%。该档只供用户独立验收，不替换 `flux2_9b_fast`，也不进入默认路由。

随后对公开 `unsloth/FLUX.2-klein-9B-GGUF` 的 `Q4_K_M`（5.91GB，SHA-256 已校验）进行了不接入实验。远端现有 `EasyUnetLoaderGGUF` 能识别模型并叠加现有 9B LoRA，但四页热执行均值为 8.615 秒，慢于 FP8 default 的 6.856 秒和 FP8 fast 的 5.185 秒；显存约 14.7GB，仅比 FP8 低约 0.9GB，第四页暗线保留降至 88.40%。因此 GGUF 只具备兼容性，不具备当前目标所需的提速/显存收益，不新增量化挡位。Nunchaku INT4 需要与当前 Python/Torch/CUDA 不匹配的社区运行时，列为未来独立 sidecar 路线。

“开源可见”不等于“允许重新分发权重”。每个候选都必须单独登记代码许可证、权重许可证和训练数据声明。

## 性能目标

| 场景 | 目标 |
| --- | --- |
| 缓存命中 | 不超过 300ms |
| RTX 4090 快速模式热模型 P50 | 不超过 2.5s |
| RTX 4090 快速模式热模型 P95 | 不超过 4s |
| RTX 4060 / 8GB | 降低分辨率，目标数秒级，不承诺与 4090 同档 |
| 连续阅读 | 当前页优先，至少预处理后续 3 页 |

## 画质验收

- 原有文字和对话框可读。
- 线稿轮廓、人物身份和构图不发生明显变化。
- 相邻页面主要角色颜色保持一致。
- 失败时显示原图，不出现空白页。
- 连续处理 100 页，显存和进程内存不持续无界增长。
- 分别记录冷启动、热模型、缓存命中数据，不能混在同一性能结论中。
