# 模型路线与验收

## 首版模型组合

| 环节 | 首版选择 | 原因 |
| --- | --- | --- |
| 基础生成 | SD1.5 动漫 checkpoint | 8GB 到 12GB 显卡可运行，4090 可做秒级低步数推理 |
| 结构保持 | ControlNet Lineart SD1.5 | 直接利用漫画线稿，减少人物和构图漂移 |
| 作品风格 | 作品级 LoRA | 体积小、便于按作品下载和热切换 |
| 通用回退 | SD1.5 通用二次元 LoRA | 只有许可证、基模和哈希全部通过才启用 |
| 画质增强 | Real-ESRGAN Anime 6B | 对动漫线条和低清页面成本较低 |

当前仓库不捆绑通用 LoRA 权重。远端现有 LoRA 中尚未确认到许可证清晰且与 SD1.5 上色基模兼容的通用候选，因此首次部署会正确回退到“无 LoRA”工作流。

## 后续候选基准

使用至少 100 页、经过授权的测试集比较：

当前已增加 `scripts/benchmark_api.py` 和 `benchmarks/` 清单格式，可记录完整 API 的实际模型档位、LoRA/角色参考生效情况、耗时、尺寸、明度与深色墨线保留。现有 3 页仅作为本地非商用冒烟集；详细准入门禁见 `benchmarks/README.md`。

- DDColor-Tiny：ONNX 速度基线，不作为漫画最佳效果的默认结论。
- manga-colorization-v2：漫画专项研究基线，发布前必须重新核对代码和权重许可证。
- SD1.5 Anime + Lineart ControlNet + IP-Adapter：8GB 主力候选。
- MangaNinja：上游许可证为 `CC BY-NC 4.0`，只用于本项目的非商用、自有主机验证，权重不提交或发布到 Git/Gitee。整页直接推理已判定不适合多格中文漫画；当前先用普通质量工作流完成整页基础上色和文字、墨线保护，再用 MAGIv2 分格与人物识别、每个人物聚焦推理、4 对纵向颜色锚点和 SAM 掩码回注覆盖可靠角色，并按镜头在 AniList 头像与 Bangumi 全身立绘之间选择参考。此前 3 页冒烟只对已匹配角色着色，测试章节恰好只剩青色系 Luce 和金色系 Elymas，造成页面颜色单一；当前实验档已改为“质量底图 + 角色参考覆盖”，并降低参考引导、限制掩码内色度。仍需在 100 页授权集上复核全页色彩、肤色、发色、服装和跨页一致性。当前仍作为独立实验档，无可靠参考或失败时回退质量工作流，不替代普通质量档，也不宣称满足快速模式秒级目标。
- Cobra 多参考上色：12GB/16GB 高质量候选，分别测试 2、4、8、12 张参考图。
- Real-ESRGAN Anime 6B：测试 1x 修复、2x 输出和文字线条清晰度。

“开源可见”不等于“允许重新分发权重”。每个候选都必须单独登记代码许可证、权重许可证、训练数据声明和是否允许发布衍生 LoRA。

## 作品 LoRA 训练

- 训练数据必须来自用户有权使用的彩页、封面、官方设定图或其他授权参考。
- 少于 10 张只作为实验，不自动发布。
- 稳定版本建议 30 张以上，并保留至少 20% 验证集。
- LoRA 学习作品画风，角色固定色还需要参考图检索和调色板约束。
- 每个版本固定基模名称、基模哈希、训练参数、推荐权重和验证结果。

## 性能目标

| 场景 | 目标 |
| --- | --- |
| 缓存命中 | 不超过 300ms |
| RTX 4090 快速模式热模型 P50 | 不超过 2.5s |
| RTX 4090 快速模式热模型 P95 | 不超过 4s |
| RTX 4060 / 8GB | 降低分辨率，目标数秒级，不承诺与 4090 同档 |
| 连续阅读 | 当前页优先，至少预处理后续 3 页 |

## 画质验收

- 原有文字和对话框可读。
- 线稿轮廓、人物身份和构图不发生明显变化。
- 相邻页面主要角色颜色保持一致。
- 失败时显示原图，不出现空白页。
- 连续处理 100 页，显存和进程内存不持续无界增长。
- 分别记录冷启动、热模型、缓存命中数据，不能混在同一性能结论中。
